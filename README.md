# dbt Docs on Streamlit in Snowflake

Serves your classic dbt docs site as a Streamlit in Snowflake app. Everything
runs inside Snowflake:

```
GitLab repo (this)  ──fetch──▶  Snowflake GIT REPOSITORY ──CREATE STREAMLIT FROM──▶  DBT_DOCS app
                                                                                       │ reads
dbt project object ──EXECUTE DBT PROJECT 'docs generate --static'──▶ dbt_artifacts.zip ─┘
        ▲                         (task, daily)                       copied to @DOCS_ARTIFACTS/latest/
```

- **App code** (`app/`) lives here and is pulled into Snowflake through the Git integration.
- **Docs content** is regenerated by a Snowflake task on your existing dbt project
  object, so docs stay fresh without redeploying the app.

## Repo layout

```
app/
  streamlit_app.py       Streamlit entrypoint – unzips and renders static_index.html
  environment.yml        Warehouse-runtime dependencies
sql/
  01_roles_and_schema.sql  Roles, warehouse, schema, grants on the dbt project object
  02_git_integration.sql   GitLab secret, API integration, Git repository object
  03_docs_stage.sql        Stage holding the generated docs
  04_refresh_procedure.sql Procedure: docs generate + copy zip to stage
  05_task.sql              Daily schedule for the procedure
  deploy_app.sql           (Re)create the Streamlit app from the repo
.gitlab-ci.yml           Redeploys the app when app/ changes on main
```

## Before you start: names to replace

Search and replace across the repo:

| Placeholder | Meaning |
| --- | --- |
| `ANALYTICS` | Database for the app objects |
| `DBT_DOCS` | Schema for the app objects |
| `ANALYTICS.DBT.MY_DBT_PROJECT` | Your deployed **dbt project object** |
| `https://gitlab.com/your-group` | Your GitLab group URL (or self-managed host) |
| `main` | Default branch, if different |

Also check the profile target in `04_refresh_procedure.sql` (`--target prod`).

## Setup

1. **Push this repo to GitLab.**
   Create an empty project in GitLab, then (the folder is already a git repo
   with one commit on `main`):
   ```bash
   cd dbt-docs-streamlit
   git remote add origin https://gitlab.com/your-group/dbt-docs-streamlit.git
   git push -u origin main
   ```
2. **Create a GitLab Project Access Token** on the repo: role *Reporter*,
   scope `read_repository`.
3. **In a Snowsight worksheet**, run the SQL files in order:
   `01` → `02` (paste the token into the secret) → `03` → `04` → `05`.
4. **Generate the docs once by hand** and check the zip landed:
   ```sql
   CALL ANALYTICS.DBT_DOCS.REFRESH_DBT_DOCS();
   LS @ANALYTICS.DBT_DOCS.DOCS_ARTIFACTS/latest/;
   ```
5. **Deploy the app** from the repo:
   ```sql
   EXECUTE IMMEDIATE FROM @ANALYTICS.DBT_DOCS.DBT_DOCS_REPO/branches/main/sql/deploy_app.sql;
   ```
6. Open **Projects → Streamlit → dbt Docs**. Give people access with
   `GRANT ROLE DBT_DOCS_VIEWER TO USER <user>;`.

## Updating the app

`CREATE STREAMLIT … FROM` copies the files once, so after changing `app/`:

- **Automatic:** set up the GitLab CI/CD variables listed in `.gitlab-ci.yml`
  (service user with role `DBT_DOCS_ADMIN`, key-pair auth). Merges to `main`
  that touch `app/` redeploy the app.
- **Manual:** in a worksheet:
  ```sql
  ALTER GIT REPOSITORY ANALYTICS.DBT_DOCS.DBT_DOCS_REPO FETCH;
  EXECUTE IMMEDIATE FROM @ANALYTICS.DBT_DOCS.DBT_DOCS_REPO/branches/main/sql/deploy_app.sql;
  ```

## Notes

- If the dbt run fails, the procedure stops before touching the stage, so the
  app keeps showing the last good docs.
- The app caches the docs for 15 minutes; the **Reload** button clears the cache.
- Snowsight's dbt project details page (DAG, lineage, compiled SQL) may cover
  many users' needs on its own; this app is for the classic docs site.
- Things to verify on the first run: that `LAST_QUERY_ID()` inside the procedure
  returns the `EXECUTE DBT PROJECT` query, and that `dbt_artifacts.zip` contains
  `target/static_index.html`.
